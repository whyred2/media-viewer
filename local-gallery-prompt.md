# Промт: Разработка локальной фотогалереи на Next.js 16

## Роль

Ты — опытный Senior Fullstack разработчик (Next.js 16, TypeScript, Node.js).

## Цель проекта

Создать высокопроизводительное локальное веб-приложение **"LocalGallery"**, которое позволяет пользователю просматривать тысячи фотографий, хранящихся в локальной папке компьютера.

## Технический стек

- **Фреймворк:** Next.js 16 (App Router, Server Actions, Server Components).
- **Язык:** TypeScript.
- **Пакетный менеджер:** pnpm.
- **Стилизация:** Tailwind CSS.
- **UI библиотека:** shadcn/ui (Cards, Dialogs, Inputs, Buttons, Dropdowns).
- **Иконки:** Lucide React.
- **Обработка изображений:** `sharp` (для изменения размера и оптимизации "на лету").
- **Управление состоянием URL:** Стандартный `useSearchParams` или библиотека `nuqs`.
- **Виртуализация:** `tanstack/react-virtual` (обязательно для производительности).

## Основные требования и Архитектура

### 1. Доступ к локальной файловой системе

- **Проблема:** Браузер не имеет прямого доступа к путям файловой системы (например, `D:/Photos`).
- **Решение:** Весь доступ к файлам должен проходить через серверную часть Next.js.
- **Сохранение конфигурации:** Реализуй механизм персистентности на сервере (например, чтение/запись файла `config.json` в корне проекта). Там должен храниться `rootDirectory`, который выбрал пользователь.
- **Startup Flow:**
  1.  При запуске приложение читает конфиг.
  2.  Если путь не задан -> Редирект на страницу `/setup`.
  3.  Если путь задан -> Открывается галерея.

### 2. Раздача и Оптимизация изображений (Server-Side)

- Создай API Route (например, `/api/image?path=...`), который читает файл с диска.
- **Оптимизация:** Интегрируй библиотеку **sharp**. Если запрос идет для сетки (grid), генерируй легкий `buffer` (resize, convert to webp/jpeg quality 80), а не отправляй оригинальный файл весом 10МБ.
- **Кэширование:** Добавь заголовки `Cache-Control`, чтобы браузер кэшировал миниатюры.

### 3. Функционал просмотра данных

- **Рекурсивное сканирование:** Утилита на базе `fs` для чтения структуры папок.
- **Режимы просмотра:**
  1.  **Folder View:** Классическая навигация по папкам (вход в папку/выход).
  2.  **Flat View (Все фото):** Рекурсивно собрать все изображения из корневой папки и всех подпапок в один плоский список.
- **Virtual Scrolling:** Поскольку фото могут быть тысячи, используй виртуализацию. Рендерить весь список в DOM нельзя.

### 4. UI/UX Детали

- **Темы:** Поддержка светлой и темной темы (`next-themes`).
- **Сетка:** Адаптивный Grid или Masonry layout.
- **Lightbox (Модальное окно):**
  - Открытие фото на весь экран.
  - Поддержка зума.
  - Навигация стрелками клавиатуры (влево/вправо).
  - Отображение названия файла (filename).
- **Setup Page:** Простой и красивый экран с input для ввода пути и валидацией существования папки.

## План реализации (Step-by-Step)

1.  **Настройка окружения:** Инициализация Next.js, установка `shadcn/ui`, `sharp`, `fs-extra` через `pnpm`. Настройка темной темы.
2.  **Backend Services:**
    - Создание сервиса `FileService` (scan directory, check path).
    - Создание сервиса `ConfigService` (read/write json).
    - Реализация `/api/image` route handler с `sharp`.
3.  **Frontend Components:**
    - `SetupScreen`: Форма ввода пути.
    - `GalleryGrid`: Виртуализированная сетка.
    - `Thumbnail`: Компонент картинки, который корректно обрабатывает загрузку.
    - `Lightbox`: Оверлей для просмотра оригинала.
4.  **Страницы:**
    - `/setup` - Страница настроек.
    - `/` - Главная страница (галерея), которая рендерит `GalleryGrid`.

## Важные ограничения

- Обрабатывай ошибки доступа к файлам (EACCES, ENOENT) gracefully (показывай тост-уведомление).
- Код должен быть модульным и типизированным.
